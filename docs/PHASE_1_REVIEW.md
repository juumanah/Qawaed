## القرارات

1. احتفظنا بالنسخة الكاملة السابقة مستقلة، وأعدنا تقديمها على مراحل فعلية. التاريخ الجديد يصرح بذلك ولا يدعي تاريخ تطوير مختلفًا.
2. فصلنا حساب الترحيلات عن حساب التطبيق لتقليل صلاحيات التشغيل. لا توجد واجهة تعرض بيانات الشركات في هذه المرحلة.
3. استخدمنا SQL صريحًا وترحيلات مقفلة وقابلة لإعادة التشغيل. لا نضيف ORM أو خدمات أخرى دون حاجة.
4. جعلنا فحص الصحة يقيس اتصال قاعدة البيانات حتى لا يعرض نجاحًا زائفًا عند تعطلها.
5. أضفنا اختبارات وحدات للسلوك واختبارات تكامل لقاعدة البيانات وHTTP. Mock قاعدة البيانات لا يكفي لإثبات عمل الترحيلات.

## النتائج

- نجح تثبيت الاعتماديات من lockfile. محاولة offline الأولى لم تنجح بسبب حزمة غير مخزنة، ثم نجح npm ci العادي.
- نجح بناء NestJS وNext.js للإنتاج وفحص TypeScript.
- نجحت 5 اختبارات: اختبارا وحدات و3 تكامل على PostgreSQL 17.11.
- تكرر setup مع الاحتفاظ بتعديل اسم الشركة دون تكرار الشركتين أو تغيير سجل الترحيل.
- المحاولة الأولى لتشغيل PostgreSQL واجهت قيد Unix sockets في البيئة؛ تم تشغيله عبر TCP ضمن نفس جلسة الاختبار.
- نجح فحص HTTP للإنتاج: الواجهة ثم proxy ثم API ثم PostgreSQL. نجح فحص الصفحة الرئيسية أيضًا.
- بعد إيقاف PostgreSQL فعلًا، أعاد مسار الواجهة `/api/health` الحالة HTTP 503 كما ينبغي. هذا فحص HTTP وليس تجربة متصفح تفاعلية.
- تشغيل Next.js احتاج hostname صريحًا بسبب قيود قراءة واجهات الشبكة في البيئة.
- Docker غير مثبت هنا، وGitHub CI لم يُشغل بعد. لا نعتبر المرحلة جاهزة للرفع النهائي حتى ينجح Compose.

## ما تختبره جمانة محليًا

1. تأكدي أن Docker Desktop يعمل.
2. شغلي `docker compose up --build` من مجلد هذه المرحلة، لا مجلد النسخة الكاملة.
3. افتحي الواجهة ثم رابط فحص الصحة، وتحققي من `database: up`.
4. شغلي أمر الاختبارات الموجود في README على قاعدة تجريبية.
5. أرسلي النتائج وأي خطأ؛ بعدها نرفع المرحلة إلى مستودع GitHub الذي تختارينه.

لا تحتوي هذه المرحلة على تسجيل دخول أو مراجعة طلبات. اختبارات التكامل الشاملة للمشروع السابق ليست دليلًا على اكتمال هذه الوظائف في هذه المرحلة.
